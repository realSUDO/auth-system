OAuth 2.0 Integration Guide

          
SudoAuth implements the OAuth 2.0 Authorization Code flow with RS256-signed JWTs. It is compatible with the OIDC standard — any library that supports OIDC discovery will work out of the box.

          

            Base URL
            https://auth.sudohq.me
          

        


        

          
Get credentials

          
Before integrating, you need a clientId and clientSecret. Submit a request with your app name and redirect URI. You will receive credentials by email once approved.

          
You will receive:

          
    
            
  • clientId — public identifier for your app
    • 
            
  • clientSecret — keep this server-side only, never expose in frontend code
    • 
          

        


        

          

            1
            
Redirect user to authorize

          

          
Build the authorization URL and redirect the user. Your UI collects the email and password — there is no hosted login page.

          
const state = crypto.randomUUID(); // store this to verify later
sessionStorage.setItem('oauth_state', state);

const url = new URL('https://auth.sudohq.me/oauth/authorize');
url.searchParams.set('client_id',     YOUR_CLIENT_ID);
url.searchParams.set('redirect_uri',  YOUR_REDIRECT_URI);
url.searchParams.set('response_type', 'code');
url.searchParams.set('state',         state);
url.searchParams.set('email',         userEmail);    // from your login form
url.searchParams.set('password',      userPassword); // from your login form

window.location.href = url.toString();

          
On success, the user is redirected to YOUR_REDIRECT_URI?code=...&state=...

          
Always verify the state parameter matches what you stored before proceeding.

        


        

          

            2
            
Exchange code for tokens

          

          
On your server, exchange the code for an access token and refresh token. Never do this from the browser — it would expose your clientSecret.

          
// server-side only
const res = await fetch('https://auth.sudohq.me/oauth/token', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    grant_type:    'authorization_code',
    code:          req.query.code,
    client_id:     YOUR_CLIENT_ID,
    client_secret: YOUR_CLIENT_SECRET,
    redirect_uri:  YOUR_REDIRECT_URI,
  }),
});

const { access_token, refresh_token, expires_in } = await res.json();
// access_token expires in 15 minutes (expires_in = 900)
// store refresh_token securely (httpOnly cookie or server session)

        


        

          

            3
            
Get user info

          

          
Use the access token to fetch the authenticated user's profile.

          
const res = await fetch('https://auth.sudohq.me/oauth/userinfo', {
  headers: { Authorization: `Bearer ${access_token}` },
});

const user = await res.json();
// {
//   sub:   "user_id",
//   email: "user@example.com",
//   name:  "User Name"
// }

        


        

          

            4
            
Refresh the access token

          

          
Access tokens expire after 15 minutes. Use the refresh token to get a new one. Refresh tokens are rotated on every use — always store the new one.

          
const res = await fetch('https://auth.sudohq.me/oauth/token', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    grant_type:    'refresh_token',
    refresh_token: storedRefreshToken,
    client_id:     YOUR_CLIENT_ID,
    client_secret: YOUR_CLIENT_SECRET,
  }),
});

const { access_token, refresh_token } = await res.json();
// store the new refresh_token — the old one is now invalid

        


        

          
Endpoints

          

            

              MethodPathDescription
            

            
GET/.well-known/openid-configurationOIDC discovery document

            
GET/jwksPublic keys (JWK format)

            
GET/oauth/authorizeAuthorization endpoint

            
POST/oauth/tokenToken exchange + refresh

            
GET/oauth/userinfoUser profile (Bearer token)

            
POST/auth/loginDirect login (first-party apps)

            
POST/auth/signupCreate account

            
GET/auth/verifyVerify a JWT (no DB call)

          

        


        

          
Token format

          
Access tokens are RS256-signed JWTs. Decoded payload:

          
{
  "sub":   "user_cuid",       // user ID
  "email": "user@example.com",
  "type":  "access",
  "iat":   1234567890,        // issued at
  "exp":   1234568790,        // expires at (15 min)
  "iss":   "https://auth.sudohq.me"
}

        


        

          
Verify tokens without calling this server

          
Because tokens are signed with an RSA private key, any service can verify them using the public key from /jwks — no network call to this server needed at runtime.

          
// Using jsonwebtoken (Node.js)
import jwt from 'jsonwebtoken';
import jwksClient from 'jwks-rsa';

const client = jwksClient({ jwksUri: 'https://auth.sudohq.me/jwks' });

const key = await client.getSigningKey('auth-key-1');
const decoded = jwt.verify(token, key.getPublicKey(), {
  algorithms: ['RS256'],
  issuer: 'https://auth.sudohq.me',
});
// decoded.sub, decoded.email, decoded.exp

          
Or use the verify endpoint directly:

          
const res = await fetch('https://auth.sudohq.me/auth/verify', {
  headers: { Authorization: `Bearer ${token}` },
});
const { valid, decoded } = await res.json();
